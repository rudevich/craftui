# Оформление макетов в Figma для импорта в craftui

Инструкция для дизайнера. craftui импортирует макет из Figma в React + CSS почти автоматически: чем предсказуемее структура макета, тем меньше ручных правок и тем точнее результат.

Два сценария:

- **Компонент** — набор вариантов из UI-кита (кнопка, инпут, таб).
- **Страница** — адаптивный экран из фреймов под брейкпоинты.

Общие правила (раздел 0) обязательны для обоих сценариев. Если правило нарушено, импорт обычно всё равно отработает — с предупреждениями, — но потребует больше правок на шаге кода.

---

## 0. Общие правила

### Размеры

- **Только `px` и `%`.** Проценты у line-height и letter-spacing не страшны — пересчитаются в px так, как рисует Figma. Прочие единицы в коде запрещены проверкой (unitless `line-height`, `fr` в сетках — исключения кода, дизайнера не касаются).
- Line-height в процентах не страшен — он пересчитается в px так, как рисует Figma.
- Отрицательный gap в auto-layout допустим (переедет отрицательными margin), но лучше избегать.

### Auto-layout

- **Auto-layout — везде**, где раскладка линейная. Auto-layout напрямую превращается в CSS flex: направление, gap, padding, fill/hug переносятся как есть.
- Абсолютное позиционирование — **только для декора**: бейджи, оверлеи, всплывающие подсказки. Это единственный допустимый случай слоёв, лежащих по x/y поверх раскладки.

### Имена слоёв

- Имена слоёв становятся CSS-классами и ключами сопоставления. **Называйте по смыслу**: `header`, `price-list`, `icon-chevron`, а не `Frame 1247`.
- Не больше ~60 символов. **Не называйте слой целым текстом**, который в нём написан, — имя обрежется.
- Обёртки без стилей (пустой фрейм-группа вокруг иконки) схлопнутся при импорте — они безвредны. Обёртка со стилями (padding, gap, фон) станет элементом дерева — если она несёт смысл, дайте ей имя.

## 1. Компонент

### 1.1 Набор вариантов и оси

- Один **COMPONENT_SET = один источник импорта**. Внутри — варианты с осями `Ось=Значение` (`Size=M, View=Accent`).
- **Лимит: 80 вариантов на набор.** В UI-китах бывают сотни (кнопка на 830 вариантов) — заранее договоритесь о приоритетных комбинациях.
- **Имена осей и значений — латиницей.** Кириллица работает, но транслитерируется: ось `Размер` станет пропом `razmer`. Пишите `Size`, `View`, `Orientation`.
- **Одно значение оси = одна черта.** `View=Secondary Outline` — плохо: «outline» запечётся внутрь значения. Отдельный признак — отдельная ось: `View=Secondary` + `Outline=True/False`.
- Если компонент собран из **нескольких наборов** (например, основной и «Outline»), каждая ось должна быть задана у всех источников: у основного `Outline=False`, у outline-набора `Outline=True`. Не смешивайте свои признаки в чужой оси.
- Булевы значения пишите ровно `True/False`, `Yes/No` или `On/Off` — тогда ось станет булевым пропом или состоянием (см. 1.2).

Хороший набор:

```
Button (COMPONENT_SET)
  оси:      Size=S|M|L,  View=Accent|Secondary|Ghost,  State=Default|Hover|Pressed|Focus|Disabled|Loading
  свойства: Label (TEXT), Icon (INSTANCE_SWAP), IconVisible (BOOLEAN)
```

### 1.2 Состояния

Ось с именем **`State` / `States` / `Status` / `Interaction` / `Состояние`** (латиницей или кириллицей) — не станет пропом: каждое её значение интерпретируется как состояние.

| Значение оси | Что получится в коде |
|---|---|
| `Default`, `Enabled`, `Rest`, `Normal`, `Idle`, `Base`, `Static` | базовый вид |
| `Hover`, `Hovered` | `:hover` |
| `Pressed`, `Press`, `Active`, `Click`, `Clicked`, `Tap` | `:active` |
| `Focus`, `Focused`, `Focus Visible` | `:focus-visible` |
| `Disabled`, `Inactive` | проп `disabled` + `:disabled` |
| `Loading`, `Busy`, `Progress` | проп `loading` + `aria-busy` |
| всё остальное | помечено как unknown и **не попадёт в код** — назовите значение из таблицы |

Альтернатива — **булевы оси, имя которых = состояние**: `Hovered=True/False`, `Disabled=True/False`, `Loading=True/False`. Они так же превращаются в состояния и, в отличие от одной оси `State`, **комбинируются**: `Hovered=True` + `Disabled=True` в одном варианте. Выдуманные значения (`State=HoverDisabled`) не распознаются.

Нюансы:

- «Focused» у пункта списка/аккордеона — это не DOM-фокус, а выбранное состояние данных. Обсудите такие оси с разработкой отдельно.
- Состояние, нарисованное чертой (весь набор с прозрачностью 0.4, «затемнённый» вариант), — не состояние для кода. Если это черновик — не включайте его в импорт.
- Оси, которые управляются данными, а не пользователем (`Value=Empty/Filled`, `Selected`), станут обычными пропами — для интерактивных компонентов это обсуждается с разработкой.

### 1.3 Свойства компонента

| Свойство в Figma | Что получится в React |
|---|---|
| **TEXT** — единственное в компоненте | `children: ReactNode` |
| **TEXT** — несколько | пропы по именам: `Caption` → `caption: string` |
| **BOOLEAN** | булев проп. Если переключает только иконку(и) — станет слотом, если текст — текстовым пропом |
| **INSTANCE_SWAP** | слот `ReactNode` (варианты из preferredValues сохранятся) |

- Если TEXT-свойств нет, но в компоненте ровно один видимый текстовый слой — импорт предложит сделать его `children`. Это сработает и для слоя, названного `Label`, `Text`, `Title`, `Caption`, `Текст`, `Подпись`.
- Слои, выключенные булевым свойством во всех вариантах, остаются в дереве компонента — не удаляйте их совсем, если они нужны скрытыми по умолчанию.

### 1.4 Слоты

Слот — место, куда потребитель кладёт своё содержимое (иконку, текст, произвольный узел).

- Ось, имя которой **начинается** с `Content`, `Icon`, `Prefix`, `Suffix`, `Addon`, `Before`, `After`, `Left`, `Right`, `Start`, `End`, и среди значений есть пустое (`None`, `False`, `No`, `Off`, `Empty`, `Нет`) → станет слотом: `ContentLeft=True/False` → `contentLeft: ReactNode`.
- **Оставьте в наборе вариант с пустым значением** и включите его в импорт: содержимое слота определяется сравнением варианта с заполненным и пустого. Без пустого варианта импорт не поймёт, какие слои — содержимое.
- Иконка, которая есть во всех вариантах и не переключается осями, тоже предложится как слот. Иконка, меняющаяся между вариантами (chevron вверх/вниз) — часть компонента, а не слот.
- **Слоту не задавайте размер содержимого.** Обёртка слота — только раскладка (отступы, выравнивание); размер иконки/текста внутри задаёт потребитель.

### 1.5 Чего избегать

- ❌ Имя слоя = длинный текст из слоя (`Закажите обратный звонок и мы перезвоним…`) — станет обрезанным ключом.
- ❌ Фиксированная высота текстового блока — в код не переносится, высоту задаст шрифт и width.
- ❌ Размеры в `rem`/`em`/`pt`.
- ❌ Ряд копий одного айтема (`item01…item12`) вместо инстансов. Сделайте айтем компонентом, а контейнер — рядом инстансов: список станет `children`/слотом.
- ❌ Безымянные слои (`Frame 1247`) и оси с кириллицей в имени.
- ❌ Библиотечные компоненты не из вашего файла: они должны быть **загружены** в файле на момент импорта. Надёжнее всего — всё в одном файле.

## 2. Страница

### 2.1 Фреймы и брейкпоинты

- Дайте ссылку на **группу/секцию с фреймами экрана** (или на каждый фрейм отдельно). Ссылка на страницу Figma целиком не подходит.
- **Один фрейм на брейкпоинт.** Ширина фрейма — любая внутри диапазона брейкпоинта: диапазоны задаются в конфиге проекта один раз (например: mobile ≤ 600, tablet 601–1024, desktop 1025+). Имена фреймов не важны — фрейм мапится на брейкпоинт по ширине.
- Два фрейма в одном диапазоне → предупреждение, оба будут считаться источниками с суффиксом ширины. Фрейма в диапазоне нет → его досверстают по соседним брейкпоинтам.
- Слой, отсутствующий на каком-то брейкпоинте, скрывается `display: none` — исчезать между брейкпоинтами нормально.

**Имена слоёв — одинаковые во всех брейкпоинт-фреймах.** Разметка всех экранов мержится в одно дерево по имени пути слоя. Если на десктопе шапка называется `header`, а на мобиле `Header Mobile`, в коде появятся два разных элемента вместо одного адаптивного.

### 2.2 Auto-layout на странице

- Вся линейная раскладка (вертикальные и горизонтальные потоки) — **в auto-layout**.
- Фрейм без auto-layout импорт не отвергнет: он конвертируется в колонку — порядок по y, зазоры станут margin, выравнивание по горизонтали сохранится. Но пересекающиеся слои уедут в `position: absolute`, и результат надо проверять скриншотами. Auto-layout предсказуемее.
- Absolute — только декор и оверлеи (бейджи, плавающие кнопки).

### 2.3 Блоки и части

- **Верхнеуровневые слои фрейма = блоки страницы** (`header`, `form`, `cards`). Из них делаются parts — внутренние компоненты страницы.
- Общие блоки на нескольких страницах (шапка, навигация, степпер) — **называйте одинаково**: они станут общими частями и переиспользуются как есть.
- Имя части — PascalCase латиницей (`Header`, `Navigation`); базовое имя возьмётся из названия слоя, поэтому называйте блоки по смыслу.
- Части **не вкладываются** друг в друга: слой внутри части — это её разметка.
- Статус-бар телефона, браузерная обвязка, рамки устройства — **device chrome**: такие слои помечаются как mockup, не верстаются, а эталон сравнивается ниже них. Держите их отдельным слоем.

### 2.4 Компоненты на странице

- Инстанс резолвится в импортированный компонент по совпадению с сущностью из **того же файла**. Порядок: **сначала импортируются компоненты, потом страница**. Неразрешённый инстанс будет сверстан inline из своих слоёв — это хуже: без API компонента.
- Страница задаёт компоненту **только позицию и размер** — API и стили компонента не трогаются. Значения пропов берутся с самого узкого фрейма; если проп различается между брейкпоинтами, это фиксируется как вопрос к разработке.
- Компонент, состоящий только из векторов (логотип), станет картинкой страницы, а не зависимостью.

### 2.5 Тексты и изображения

- **Реальные тексты**, не lorem ipsum — тексты переносятся в код дословно.
- Изображения присутствуют в макете; alt добавит разработка.
- Семантику (`header`/`main`/`footer`, `h1`–`h3`) разработка добавит на шаге кода — макету достаточно структуры и осмысленных имён слоёв.

### 2.6 Ограничения

- До **15 000 узлов** на источник страницы (для компонента — 5000). Очень большие экраны делите на части или отдельные источники.
- Широкий блок фиксированной ширины (≥ половины фрейма) станет `width: 100%` + `max-width` — это ожидаемо.
- Размеры — только `px` и `%`, включая условия контейнерных запросов. Медиазапросы по окну не используются: адаптив строится по ширине самой страницы.

## 3. Чеклист перед отдачей

**Компонент**

- [ ] Оси и значения латиницей, одно значение = одна черта (`View=Secondary` + `Outline=True`, не `View=Secondary Outline`)
- [ ] Состояния — ось `State` со значениями из таблицы (или булевы оси `Hovered`/`Disabled`/`Loading`, если нужны комбинации)
- [ ] У слотовых осей есть пустое значение (`None`), и вариант с ним включён в импорт
- [ ] Не больше 80 вариантов в наборе
- [ ] Текстовые пропы заведены как TEXT-свойства
- [ ] Auto-layout везде, кроме декора; absolute — только бейджи и оверлеи
- [ ] Размеры только px и %
- [ ] Слои названы по смыслу, без `Frame 1247` и текста-простыни в именах

**Страница**

- [ ] Группа экранов: один фрейм на брейкпоинт, ширина внутри диапазона
- [ ] Имена слоёв одинаковы во всех брейкпоинт-фреймах
- [ ] Компоненты, использованные на странице, импортированы раньше неё
- [ ] Общие блоки (шапка, навигация) названы одинаково на всех страницах
- [ ] Device chrome (статус-бар, обвязка браузера) — отдельным слоем
- [ ] Реальные тексты и изображения
- [ ] Не больше 15 000 узлов на экран
