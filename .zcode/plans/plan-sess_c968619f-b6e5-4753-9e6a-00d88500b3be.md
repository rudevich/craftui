## Context

Плагин craftui (`.claude-plugin/plugin.json`) теперь объявляет `mcpServers` → `node ${CLAUDE_PLUGIN_ROOT}/mcp/server.ts`. ZCode умеет это исполнять: манифест в `.claude-plugin/` распознаётся как совместимое имя, серверы плагина образуют базовый слой MCP и **подключаются автоматически** при старте сессии. Тест проверяет четыре риска: (1) регистрацию локального маркетплейса, (2) подъем сервера (расширение `${CLAUDE_PLUGIN_ROOT}` и **Node ≥ 24** — дефолтный node машины 23.6, сервер при старте проверяет версию), (3) cwd сервера = workspace, (4) скил не затенён другой копией.

Изменений в репозитории не требуется; фолбэки правят только `~/.zcode/cli/config.json`.

## Шаг 0 — pre-flight (я)

- `ls ~/.zcode/skills ~/.agents/skills` — нет ли уже скилла `craftui` в user-scope (он затенил бы плагинный; plugin-skiллы имеют самый низкий приоритет).
- Свежий smoke: `node mcp/smoke.ts` (Node 24 через nvm).
- Проверить `.claude-plugin/marketplace.json` (`{name, plugins:[{source:"./"}]}` — поддерживаемый формат).

## Шаг 1 — регистрация (ты, ~1 минута, GUI)

1. **Settings → Plugin Management → Discover → «+»** → добавить локальный каталог `/Users/rudevich/work/craftui` (там лежит `marketplace.json`).
2. На карточке плагина **craftui** нажать **Get / Installed** (включён по умолчанию).
3. Начать **новую сессию** (компоненты плагина подгружаются на старте).

## Шаг 2 — проверка подключения (я, в новой сессии)

- В сессии должны появиться инструменты `mcp__craftui__*` (я вызываю `status`).
- `Settings → MCP` — сервер `craftui` connected; в логе сервера строка `craftui mcp 0.2.0: проект — <cwd>`.
- `Settings → Skills` / меню `/` — скилл `craftui` присутствует.
- Инспект `~/.zcode/cli/config.json` → секция `plugins` (запомню схему для будущего).

## Шаг 3 — функциональный прогон

- **Workspace = playground**: я вызываю `mcp__craftui__status` (ожидание: 12 сущностей, «Всё импортировано»), `next` («Незавершённой работы нет»), `config` без аргументов (текущие брейкпоинты) — это подтверждает cwd = workspace.
- Ошибка как данные: `create` с битой ссылкой → чистый `isError`-результат с текстом, сервер жив.
- **Workspace = репозиторий craftui**: `status` → аккуратная ошибка «нет craftui.config.json» (cwd-guard), сервер не падает.
- `/craftui help` → агент пересказывает `references/help.md` и ничего не делает.

## Шаг 4 — фолбэки

- **Сервер не подключился / упал по версии node** (23.6 в PATH): пользовательский override — в `~/.zcode/cli/config.json` добавить `mcp.servers.craftui` с явным `command: "/Users/rudevich/.nvm/versions/node/v24.19.0/bin/node"`, `args: ["/Users/rudevich/work/craftui/mcp/server.ts"]` (user-слой переопределяет плагинный для того же имени — документировано), новая сессия, повторить шаг 2. Альтернатива — перезапустить ZCode из шелла с активным nvm 24.
- Если не расширяться `${CLAUDE_PLUGIN_ROOT}` — тот же override с абсолютным путём решает и это.
- Дальнейшая диагностика по скиллам `diagnosing-mcp` / `diagnosing-plugins`.

## Шаг 5 (опционально) — хуки под ZCode

`hooks install` craftui пишет `.claude/settings.json` / `.codex/hooks.json` — **ZCode их не читает**. Для проверки `hook.ts` под ZCode: в `playground/.zcode/config.json` добавить блок `hooks` (`enabled: true`, событие `stop` → `node <repo>/mcp/hook.ts stop`) — точную схему возьму из скилла `diagnosing-hooks` на месте. Без этого шага хуки в ZCode просто не действуют, тестировать их не обязательно.

## Verification

Чек-лист шагов 2–3 и есть критерий: `mcp__craftui__*` в сессии, сервер connected с cwd=workspace, статус playground отвечает, ошибки возвращаются как данные без падения сервера, скилл виден и `/craftui help` работает.
