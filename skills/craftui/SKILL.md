# craftui — Figma → React-компоненты

`<skill>` ниже — папка этого файла. Подробности лежат в `<skill>/references/`. Читай только тот файл, который нужен на текущем шаге. Всю детерминированную работу выполняют команды `npm run craftui -- …` в проекте: они сами пишут состояние и подсказывают следующий шаг. В проекте есть копия этих инструкций: `.craftui/skill/`.

## 0. Аргументы вызова

Аргументы берутся из текста вызова или сообщения пользователя:
- `help`, `помощь`, `?` → покажи пользователю `<skill>/references/help.md` (кратко пересказав разделы) и больше ничего не делай;
- `<ссылка Figma> [через chrome | через mcp]` → **A. Новый импорт**;
- `continue [Name]` / «продолжи» → **B. Продолжение**;
- `fix <Name> <задача>` / «поправь …» → **C. Правки**;
- `resync <Name>` / «макет изменился» → **D. Ресинк**;
- `status` или без аргументов → `npm run craftui -- status`, затем спроси, что делать.

## 1. Правила (всегда)

1. **План перед действиями.** Сначала только читай: ссылку, `craftui.config.json`, `npm run craftui -- status`, логи. Затем покажи пронумерованный план (1, 2, 3…): какие узлы Figma и каким источником, какие папки и файлы создашь или изменишь, какие команды запустишь, что проверишь. Спроси «Принять / Отклонить / Правки». Если отклонили — ничего не делай и уточни. Если план по ходу существенно меняется (вложенные компоненты, другой источник, ресинк) — покажи новый план и снова спроси. Принятый план запиши: `npm run craftui -- log <Name> "план: …"`.
2. **Вопросы пользователю.** Задавай их встроенным инструментом вопросов, если он есть (AskUserQuestion в Claude Code). Если такого инструмента нет — задай вопрос обычным сообщением и заверши ход. Перед таким вопросом обязательно выполни `npm run craftui -- wait <Name> "<вопрос>"`, после ответа — `craftui resume <Name>`.
3. **Чекпоинты.** Каждый шаг выполняется так: `craftui begin <Name> <step>` → работа → `craftui done` (или `craftui fail <Name> <step> "<ошибка>"`). Шаги идемпотентны, повтор ничего не ломает.
4. **Береги контекст.** Сырые ответы Figma сразу сохраняй в файлы и не перечитывай целиком: дальше работай по сводкам `craftui normalize/verify`. Длинный вывод команд направляй в файл, а смотри `tail`.
5. **Сбой API, лимит, обрыв, потеря контекста.** Повтори тот же шаг (до 3 раз с паузой). Если после рестарта не помнишь, что делал, — `npm run craftui -- next`. Подробнее: `references/recovery.md`.
6. **Вход в Figma делает только пользователь.** Логины и пароли никогда не вводи. Если в браузере просят вход или доступ — явно скажи об этом пользователю и жди (см. `figma-chrome.md`).
7. **Код** пиши по `references/code-conventions.md`: минимум, что нужно макету, доступность не урезать. Размеры только в `px` и `%`; содержимому слотов компонент размер не задаёт.
8. **Каждый итоговый отчёт** заканчивай 1–2 строками: что не проверено и какие риски.

## 2. Вход

- В папке есть `craftui.config.json` → выполни `npm run craftui -- status`. Если есть незавершённая работа и пользователь не просил другого — переходи к **B**.
- Проекта нет → в плане (правило 1) предложи развернуть его: `node <skill>/scripts/init-project.mjs`, затем `npm install --no-audit --no-fund > .craftui/install.log 2>&1` и `npx playwright install chromium`. Нужна Node.js `^20.19 || >=22.12`. Если скрипт сообщает о чужом package.json — спроси: библиотека в подпапке или `--merge`.
- Обновить инструменты в существующем проекте: `node <skill>/scripts/init-project.mjs --update`.
- Для Claude Code и Codex предложи в плане автопродолжение: `npm run craftui -- hooks install`. Это постоянная настройка проекта, поэтому только с согласия пользователя.

## 3. A. Новый импорт

1. `npm run craftui -- url "<ссылка>"`. Если проекта ещё нет — `node <skill>/template/scripts/craftui/cli.mjs url "<ссылка>"`. Если в ссылке нет node-id — попроси ссылку на слой (ПКМ → Copy link to selection).
2. **Источник:** из сообщения пользователя → `source` в `craftui.config.json` → иначе спроси (Figma MCP или Chrome). Проверь, что инструменты доступны. Если Figma MCP требует авторизации — скажи пользователю, как её пройти (в Claude Code: `/mcp`).
3. **Разведка без записи:** узнай тип узла и имя (metadata через MCP или проба в Chrome: `craftui snippet "<ссылка>" probe` — см. references источника).
   - COMPONENT_SET / COMPONENT → один компонент.
   - INSTANCE → предложи импортировать его главный компонент.
   - PAGE или секция UI-кита → список наборов. Компонент может состоять из нескольких наборов (по размерам, outline) — тогда это одна сущность с несколькими источниками. Несколько разных компонентов → выбор, очередь (`kind-component.md`, «UI-кит»).
   - Сотни вариантов в наборе → вместе с пользователем выбери приоритетные targets и задай фильтр (`figma-chrome.md`, «Разведка»).
   - Экран (страница приложения) → скажи, что вид `page` появится в следующей версии, и предложи импортировать его компоненты.
4. **План → подтверждение** (правило 1), отдельно — **имя компонента**: PascalCase из имени в Figma как первый вариант (`Button / Primary` → `Button`, кириллицу транслитерируй или переведи), с проверкой, что такой папки ещё нет.
5. `npm run craftui -- new component <Name> "<ссылка>" --source chrome|mcp [--variant "Size=M"] [--filter <файл>]`, затем остальные наборы: `craftui source <Name> add …`.
6. Дальше цикл: `npm run craftui -- next <Name>` печатает шаг и точные команды → выполняешь → `craftui done`. Шаги компонента: extract → normalize → confirm (свойства и targets — подтверждает пользователь; строки `?` сводки — предложенные слоты, их тоже) → screenshots → deps (вложенные компоненты импортируются раньше родителя: `craftui new … --parent <Name>`) → tokens → scaffold → code → tests → verify (до 5 итераций) → report.
7. Итоговый отчёт — по `references/log-format.md`. `craftui done <Name> report` закрывает версию импорта и пишет `README.md` в папке компонента. Затем пригласи пользователя дать правки.

## 4. B. Продолжение

`npm run craftui -- next` (без имени — по всему проекту: сначала вложенные, потом родители). Покажи план оставшихся шагов → подтверждение → цикл из A.6.

## 5. C. Правки от пользователя

Прочитай лог (`src/<kind>/<Name>/craftlog/craftui.log.md`) и файлы компонента. Покажи план правки и получи подтверждение. Внеси правку и прогони `npm run craftui -- verify <Name>` (для затронутых состояний `--grep <id>`). Запиши задачу и результат: `craftui log`.
- Пользователь сознательно отходит от макета → раздел «Отклонения от макета» в логе плюс порог или маска в `craftlog/visual/visual.config.json` (`references/verify.md`). Эталон Figma не переписывай.
- Новое поведение → добавь rstest-тест.

## 6. D. Ресинк с Figma

План → `npm run craftui -- reopen <Name> extract "<причина>"` (причина попадёт в историю версий README) → заново шаги extract, normalize (`--keep` сохраняет ручные правки props и targets и добавляет новые значения) и screenshots. Новые targets добавь в демо: `craftui scaffold <Name> --add-targets`. Затем `verify` покажет, какие состояния разошлись с обновлённым макетом. Обнови код и тесты и запиши итог в лог. Так же добавляются новые наборы (размеры, outline): `craftui source <Name> add …` → `reopen`.
