# Токены (`src/tokens.css`)

`npm run craftui -- tokens <Name>` добавляет в `src/tokens.css` недостающие токены из `spec.json`. Существующие значения он никогда не перезаписывает.

## Откуда токены

| Figma | Токен |
|---|---|
| переменная `Colors/Text/Primary` | `--colors-text-primary` (если у переменной задан code syntax WEB — берётся он) |
| моды коллекции | мод по умолчанию → `:root`; другие моды → `[data-<коллекция>="<мод>"]`: «01. Theme» 🌑 Dark → `[data-theme="dark"]`, «02. SubTheme» onDark → `[data-sub-theme="on-dark"]`; селектор пишется, только если значение в моде отличается |
| алиас переменной | раскрывается до конкретного значения отдельно для каждого мода |
| FLOAT со scope «вес шрифта» / «прозрачность» | число без единиц, остальные FLOAT → `px` |
| paint-стиль `Primary/500` | `--color-primary-500` |
| effect-стиль `Elevation/2` | `--shadow-elevation-2` (готовый `box-shadow`) |
| text-стиль, привязанный к переменным | размер, межстрочный интервал (проценты — до целых px, как рисует Figma) и т. д.; значения по модам переменных — в тех же `[data-typography="…"]`, что у самих переменных |
| мод на слое (Theme=Dark у кнопки на градиенте) | атрибут на элементе в черновике: `data-theme="dark"`; мод по умолчанию атрибута не даёт |
| text-стиль `Body/M` | `--font-body-m-size`, `-line-height`, `-weight`, `-family`, `-letter-spacing` |

`tokenPrefix` в `craftui.config.json` добавляется ко всем именам (`--ds-…`).

## Правила

- В `css` узлов spec переменные Figma уже заменены на `var(--наш-токен)`, их можно переносить в стили как есть.
- Общее значение (используется несколькими компонентами или привязано к переменной или стилю Figma) — токен в `tokens.css`. Значение, которое встречается только в одном компоненте и ни к чему не привязано, остаётся в его `styles.module.css`.
- **Конфликт** (токен с тем же именем, но другим значением) команда только сообщает. Спроси пользователя, какое значение верное: макет мог измениться, а мог быть изменён `tokens.css`.
- **Почти равные** цвета (≤ 4/255 по каналу, `≈` в выводе) — обычно копия той же библиотеки в другом файле кита. Остаётся значение `tokens.css`, команда пишет это в историю лога; спрашивать не нужно, но упомяни в «Отклонениях».
- Одинаковые значения под разными именами — это нормально (семантика разная), не объединяй их.
- Токены удаляет только пользователь.
- Темы: компоненты используют только `var(--…)`, переключение — атрибутами `data-theme`, `data-sub-theme` и т. д. на корне приложения или контейнере. Мод, заданный в макете на слое, черновик ставит на его элемент; на экземпляре компонента — пропом `data-theme="…"`, стили компонента не меняются.
- **Слоистые киты** (Salute/Plasma и похожие) держат переменные с одинаковыми именами в разных коллекциях: SubTheme ссылается на Theme. В CSS это стало бы `--x: var(--x)` (цикл), поэтому значения раскрываются до конкретных. Сочетания модов разных коллекций (dark × on-dark) отдельно не генерируются — `shortcut`, добавить, если понадобится.
