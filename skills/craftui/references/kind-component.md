# Вид component

## Файлы

```
src/components/<Name>/
  index.ts              export { <Name> } from './<Name>'; export type { <Name>Props } from './types';
  <Name>.tsx            компонент
  styles.module.css     стили (CSS Modules)
  types.ts              <Name>Props
  constants.ts | hooks.ts | utils.ts | icons.tsx   только если есть что положить
  <Name>.demo.tsx       targets для демо и скриншот-тестов
  README.md             для людей: свойства, версия и дата импорта, проверка, история (генерируется)
  craftlog/              всё про импорт: лог, state.json, figma/, visual/, tests/
```

`craftui build {"action":"scaffold","entity":"<Name>"}` создаёт заготовки всех файлов из `spec.json`, в том числе черновики: разметку `<Name>.tsx` по слоям target `default` и `styles.module.css` (база по default, правила на каждое значение свойства и на сочетания). На шаге code их доводят, а не пишут заново. Существующие файлы scaffold не трогает (перезапись — поле "force":true).

## spec.json — источник данных

Целиком его не открывай: сотни килобайт не помещаются в контекст, а в проекте чтение запрещено (`.claude/settings.json`). Смотри данные через `craftui digest {"action":"brief","entity":"<Name>"}` и `craftui digest {"action":"spec","entity":"<Name>","target":"<target>","layer":"<слой>"}`, свойства правь через `craftui spec {"action":"prop",…}`. Схема ниже нужна, чтобы понимать вывод этих команд.

- `props[]`: свойство Figma → React (`role`: prop | state | text | bool | slot, `react`, `reactType`, `map`).
- `targets[]`: по одному на вариант. `id` совпадает с именем эталона, `props` и `pseudo` — для демо, `size` — размер в Figma, `frame` — фиксированная ширина или высота обёртки, `tree` — дерево слоёв.
- Узел `tree`: `key` (путь из имён слоёв, одинаковый во всех вариантах), `css` (CSS из Figma, переменные уже заменены на `var(--token)`), `tokens` (свойство → токен), `expect` (что проверит style-check), `text`, `instance` (вложенный компонент), `asset` (SVG-файл), `absolute`, `slot` (узел — содержимое слота, см. ниже).
- `targets[].slots` — что лежит в слотах этого варианта: `{ contentLeft: { key, name, kind: graphic | text | mixed, size, asset } }`.
- `instances[]` — вложенные компоненты и их `resolution`; `assets[]`, `fonts[]`, `tokens[]`.

`craftlog/figma/node-map.json` сопоставляет `key` слоя и класс CSS Modules (`"root/label": "label"`). Style-check находит элементы по этим классам, поэтому классы в коде должны совпадать с картой. Правила карты:
- normalize только дописывает новые ключи с предложенными именами (`label2`, `icon2424`) — переименуй их по смыслу;
- несколько ключей могут вести в один класс (подпись в разных вариантах лежит по-разному);
- `null` — у слоя нет своего элемента (обёртка Figma), style-check его пропускает.

**Обёртки схлопываются.** Фрейм варианта, оболочка инстанса или группа без своих стилей вокруг ребёнка того же размера не попадают в дерево: ребёнок получает ключ обёртки. Поэтому `root` — это обычно сама кнопка, и ключи совпадают во всех вариантах и наборах (`root/content/label`). Фреймы раскладки дизайнера (с gap) остаются.

## Свойства из Figma → React API

| Figma | React |
|---|---|
| VARIANT `Size=S/M/L` | `size?: 's' \| 'm' \| 'l'` → `data-size` на корне |
| VARIANT `State=Default/Hover/Pressed/Focus` | без пропа: CSS `:hover`, `:active`, `:focus-visible` (в демо — `pseudo`) |
| VARIANT `State=Disabled` | `disabled` (у `<button>` — нативный атрибут) + `:disabled` в CSS |
| VARIANT `State=Loading` | `loading?: boolean` → `aria-busy`, блокировка клика |
| VARIANT `true/false` | `boolean` |
| TEXT (одно) | `children` |
| TEXT (несколько) | строковые пропсы по смыслу (`label`, `hint`) |
| BOOLEAN `Show icon` | обычно слот: `icon?: ReactNode` (если показ иконки решается её наличием) или `boolean` |
| INSTANCE_SWAP `Icon` | `icon?: ReactNode` |

Normalize распознаёт и типичные для китов формы:
- **булевы оси состояний** (`Hovered=True/False`, `Actived`, `Disabled`, `Loading`) — как `State`;
- **оси-слоты** (`ContentLeft=True/False`, `ContentRight=None/Icon/Value`) → `ReactNode`. В демо они приходят заглушками `slot('icon')`, которые ты заменяешь содержимым из макета;
- **подпись без TEXT-свойства** (текстовый слой или inline-компонент Label) → `children`.

**Постоянное содержимое.** Иконка, которая есть во всех вариантах и не включается никакой осью (IconButton), сравнением вариантов не находится. Normalize ищет её сам и пишет в сводку строку `? «icon-24×24» 24×24 есть во всех вариантах — вероятно, содержимое …` с готовой командой. Согласуй с пользователем имя пропа (обычно `children`) и привяжи: `craftui spec {"action":"slot","entity":"<Name>","target":["@root/content","@root/content/icon"],"prop":"children"}`. Ключей может быть несколько: в разных размерах иконка лежит по-разному, для каждого варианта берётся первый подходящий. Значение оси так же отдаётся отдельному пропу: `craftui spec {"action":"slot","entity":"<Name>","target":["ContentRight=Value"],"prop":"hint"}`. Вложенные компоненты, которые встречаются только внутри слота, получают `resolution: content` (пример содержимого, его передаёт потребитель) и импорта не требуют. У компонента без текста (только иконка) `aria-label: string` обязателен в типах, `children` тоже.

**BOOLEAN-свойства, показывающие слой.** Если BOOLEAN включает иконку, normalize делает из него слот (`ContentLeft` → `contentLeft?: ReactNode`), если текст — текстовый проп (`Caption` → `caption?: ReactNode`). Слои, которые такое свойство выключает во всех вариантах, остаются в дереве с пометкой `hidden`: стили есть, style-check их не сравнивает, в эталонах их нет. Если BOOLEAN включает вложенный компонент (Tooltip у заголовка), реши с пользователем, чем он станет. Обычно это слот: `craftui spec {"action":"slot","entity":"<Name>","target":["@root/title/hint"],"prop":"hint"}`, а сам BOOLEAN — `react: null`.

Если одна ось макета в React естественнее разбивается на два пропа (ContentRight=Icon → `contentRight`, ContentRight=Value → `hint`), согласуй это с пользователем. Затем поправь `spec.json` (`props`, `targets[].props`) — normalize с "keep":true сохранит эти правки.

Пропсов, которых нет в макете, не добавляй. Пропущенное перечисли одной строкой в отчёте. Значения по умолчанию бери из Figma.

## Несколько наборов: размеры, outline

Если компонент в ките разбит на наборы (`BasicButton 64 XL` … `Button 24 XXS`, отдельный `…Outline`), это одна сущность с несколькими источниками (`craftui sources {"entity":"<Name>","action":"add","variant":"Size=XL"}`, см. `figma-chrome.md`). Ось из поля variant становится пропом (`size`).

- **Ось задаётся у всех источников.** Чтобы набор `…Outline` дал булев проп `outline`, у него в поле variant "Size=M, Outline=True", у остальных Outline=False. Иначе ось будет только у части targets. `craftui sources {"entity":"<Name>"}` предупреждает, если ось задана не всем. Не смешивай наборы в чужой оси (`View=Secondary Outline`): отдельный признак — отдельный проп. Сменил `variant` у источников — заново extract (`craftui step {"action":"reopen","entity":"<Name>","step":"extract"}`), normalize с "keep":true выбросит значения, которых больше нет.
- Набор может отличаться от основного не только цветом: у IconButtonOutline XS другой радиус, XXS — 28px вместо 24px. Сверяй геометрию по каждому источнику.

В CSS размерные значения задаются переменными на корне, а базовые правила общие:

```css
.root[data-size='m'] { --cu-height: 48px; --cu-py: 11px; --cu-px: 20px; --cu-gap: 4px; --cu-font-size: var(--font-body-body-m-b-size); }
.root { height: var(--cu-height); padding: var(--cu-py) var(--cu-px); gap: var(--cu-gap); font-size: var(--cu-font-size); }
```

Добавить наборы к уже импортированной сущности — режим D: `craftui sources {"entity":"…","action":"add"}` → `craftui step {"action":"reopen","entity":"<Name>","step":"extract"}` → шаги заново. Новые targets попадают в демо командой `craftui build {"action":"scaffold","entity":"<Name>","addTargets":true}`, ручные правки демо сохраняются.

## Разметка и стили

- Корневой тег — по смыслу: кнопка → `<button type="button">`, ссылка → `<a>`, поле → `<input>`/`<label>`, иначе `<div>`/`<span>`. Пропсы расширяют `ComponentPropsWithRef<'tag'>`. В React 19 `ref` — обычный проп, `forwardRef` не нужен.
- Варианты — `data-*` атрибуты на корне, селекторы `.root[data-size='m']`. Состояния — псевдоклассы, без JS.
- **Слот не задаёт размер содержимому.** Узлы с `slot` в spec — это то, что передаёт потребитель (иконка, значение), а не часть компонента. Их `width`/`height` и оформление в CSS компонента не переносятся. Обёртка слота — только раскладка: `.slot { display: inline-flex; align-items: center; }`. Иначе текст в `contentRight` сожмётся до размера иконки. Размер содержимого идёт туда, где оно создаётся: в иконку (`<IconX size={16} />`, `craftui build {"action":"svg",…}` даёт проп `size`) и в пресеты демо. Для текстовых слотов (`kind: 'text'`, например `hint`) компонент может задать типографику текста, но не размеры. Исключение — только явная рамка вокруг слота в самом компоненте (отдельный фрейм с отступами или фоном, не помеченный `slot`).
- Корень: `className={cx(styles.root, className)}` и `{...rest}`, чтобы пользователь мог дополнять стили и атрибуты.
- Box model как в Figma: `box-sizing: border-box` (`.root, .root *, .root *::before, .root *::after { box-sizing: border-box; }`).
- Текст: `-webkit-font-smoothing: antialiased` на корне. Иначе Chrome на macOS рисует текст заметно жирнее, чем Figma.
- Обводка Figma «inside» не сдвигает содержимое: используй `box-shadow: inset 0 0 0 1px …`, а не `border`.
- Варианты с разными цветами — через CSS-переменные на корне (`--cu-bg`, `--cu-bg-hover`), а правила `:hover`/`:active`/`:disabled` пишутся один раз и не срабатывают у disabled/loading: `.root:hover:not(:disabled):not([data-loading])`.
- Loading: содержимое скрывай `opacity: 0`, как в Figma. `visibility: hidden` убирает подпись из доступного имени кнопки.
- Auto-layout → flex (`gap`, `padding`, `align-items`, `justify-content`). Hug — без ширины, Fill — `flex: 1` или `width: 100%`. Fixed-размеры корня в CSS не зашивай: ширину задаёт потребитель, в демо её задаёт `frame`.
- Абсолютное позиционирование — только для слоёв с `absolute: true` (бейджи, декор).
- Цвета, отступы, радиусы, тени, типографика — через `var(--token)`, если в `tokens` узла указан токен. Иначе — значение из `css`.
- Фиксированные высоты текстовых блоков из Figma не переносятся.

## Общее у компонентов

Если у компонентов кита одна палитра или одна деталь (BasicButton и IconButton: цвета view, спиннер), не копируй её в каждый компонент.
- Палитра — `src/lib/<группа>.module.css`, например `buttonViews.module.css`: правила `.views:where([data-view='accent']) { --cu-bg: …; --cu-color: … }` только задают переменные. Компонент подключает класс вторым (`cx(views.views, styles.root, className)`) и красит: `background: var(--cu-bg)`. `:where()` оставляет правилам вес одного класса, поэтому переопределение компонента `.root[data-view='secondary']` выигрывает при любом порядке CSS.
- Общий файл описывает то, что совпадает в макетах. Где макет компонента отличается, компонент переопределяет переменные у себя, а в «Отклонения» лога пишется, что и почему. Решение, какой макет считать верным, — за пользователем.
- Переменные наследуются: в общем файле сбрасывай необязательные (`.views { --cu-bg-hover: initial; }`), иначе view без hover возьмёт значение предка.
- Custom properties в CSS Modules глобальны (`dashedIdents: false` в конфигах rspack): `--cu-*` из `src/lib/` и из компонента — одни и те же переменные.
- Общая часть с разметкой (спиннер, ряд чипов в полях Select и TextField) — `src/lib/<Part>.tsx`. Размер и положение задаёт компонент своим классом (`<Spinner className={styles.spinner} />`), чтобы style-check нашёл его по `node-map`.

## Вложенные компоненты и иконки

- Вложенный компонент, импортированный как сущность (`resolution: entity:…`), подключай импортом из соседней папки: `import { Icon } from '../Icon'`. Библиотека соберёт это как импорт, без дублирования кода.
- Не импортирован → сначала импортируй его (`craftui spec {"action":"deps",…}` подскажет команду, в том числе для библиотечного набора — по id).
- Внутренние части компонента из библиотеки (ячейка, чекбокс, оболочка списка) часто вложены в несколько уровней: `craftui spec {"action":"deps","entity":"<Name>","inlineAll":true}` встраивает все неразрешённые части уровень за уровнем и сам перезапускает normalize. Импортированные сущности при этом остаются сущностями.
- В ките бывают **наборы-двойники** (`.Item/Select/M` рядом с `.Item/Select/Default/M`): один из них импортирован, другой встречается в вариантах родителя. Объяви: `craftui spec {"action":"deps","entity":"<Name>","sameInstance":"<имя двойника>","sameEntity":"<Entity>"}`. Объявление сохраняется в spec и срабатывает, даже если инстанс появится только после встраивания родителя. Разницу между двойниками впиши в «Отклонения».
- Простая иконка или часть компонента из библиотеки (`resolution: inline`: подпись Label, иконка, внутренняя оболочка набора) разворачивается в дереве spec. Её стили и текст — часть этого компонента.
- SVG-ассет → TSX: `craftui build {"action":"svg","entity":"<Name>","asset":"<asset.svg>","name":"<IconName>"}`. Одноцветные иконки получают `currentColor`, `aria-hidden` и `focusable="false"`. Иконки компонента клади в `icons.tsx`, иконки только для демо (содержимое слотов) — прямо в `<Name>.demo.tsx`, чтобы они не попали в библиотеку.
- Градиенты вида conic (спиннеры) Figma экспортирует через `foreignObject`: такое проще нарисовать на CSS (`conic-gradient` + `mask`).

## Интерактивные компоненты (Select, Tabs, Accordion…)

В Figma есть только состояния (Opened, Value=Filled, Selected, Focused), поведения там нет. Порядок такой:
- **API.** Каждое состояние, которым управляет потребитель, — пара «управляемый + неуправляемый» проп, как у нативных полей: `value` / `defaultValue` / `onChange`, `open` / `defaultOpen` / `onOpenChange`. Хук `useControlled` — из `src/lib/useControlled.ts`. Оси, которые следуют из данных (`Value=Empty/Filled`, `EmptyState`), пропсами не становятся: их задают данные (`value`, пустой `options`). Сочетания, которых нет в макете, запрещай типом (`value: string[]` только с `multiple`).
- **Доступность.** Разметку и клавиатуру бери из паттерна WAI-ARIA APG: select-only combobox, tabs, disclosure, grid, date picker dialog. Подсветка пункта при навигации — это проп (`active`) и `aria-activedescendant`, а не DOM-фокус: фокус остаётся на поле. Состояние Figma «Focused» у пункта — это и есть active.
- **Сетка** (календарь, таблица выбора) — APG grid: `role="grid"` / `row` / `gridcell`, в tab-порядке одна ячейка (`tabIndex` 0, остальные −1), стрелки, Home/End и PageUp/PageDown переносят DOM-фокус. Ячейке, которая станет фокусной, ставь атрибут (`data-focus-target`) и фокусируй её в эффекте после перелистывания.
- **Поле с маской** (дата, телефон) — нативный `<input>` с `inputMode="numeric"`. Маска применяется в `onChange`, значение разбирается по Enter и `blur`. Нечитаемое значение — `aria-invalid` и вид error, `onChange` не вызывается. Функции формата и разбора без React клади в `src/lib/` (`dates.ts`) и тестируй отдельно.
- **Составной компонент** (поле + календарь) собирай из импортированных сущностей (TextField, Calendar), не копируя их стили. Иконка, которая открывает оверлей, — `<button>` без собственного размера, с `aria-haspopup` и `aria-expanded`. Открытый по кнопке оверлей забирает фокус, Esc и выбор возвращают его в поле, нажатие снаружи и уход фокуса закрывают оверлей.
- **Демо.** Targets задают состояния Figma теми же пропсами (`open: true`, `value: 'i1'`). Данные подбирай под эталон: число пунктов (по скроллбару), какие отмечены (по `instance.variant` пунктов в spec).
- **Оверлей** (список, поповер) — `position: absolute` у обёртки поля, отступ — из макета. Тогда эталон с `bounds.json` совпадёт. Выпадашка рисуется поверх соседнего контента и ничего не сдвигает; витрина демо запасает место только под состояния, открытые при загрузке (`demo/Room.tsx`).
- **Часть макета не делаем** (быстрые периоды у календаря) — закрой маской только несравнимое: содержимое и смещённые края. Совпадающие края, отступы и тени оставь в сравнении (`verify.md`, «Маски»).
- **Весь набор в Figma с opacity** (черновик, 0.4 у корня каждого варианта) — у компонента такого состояния нет. В демо приглуши targets тем же `style: { opacity: 0.4 }` и запиши это в «Отклонения».
- **Обрезанное в макете содержимое остаётся доступным** (ряд чипов, длинные вкладки). Оно прокручивается без видимой полосы, колесо мыши двигает ряд, а на его краю прокрутка уходит странице. Только что добавленное прокручивается в видимую область (`scrollIntoView({ inline: 'nearest' })`), при первом рендере ничего не двигается, поэтому эталоны не меняются.
- **rstest.** Открытие и закрытие мышью и клавиатурой, выбор, `aria-*` состояния, управляемый режим, блокировка при `disabled` / `readOnly`, запреты в типах (`@ts-expect-error`).
- **Вложенный пункт** (SelectItem) — отдельная сущность из своего набора: у него свои состояния и эталоны. Родитель рендерит его и не дублирует стили.

## UI-кит: пакетный импорт

1. По ссылке на страницу или секцию кита собери список COMPONENT_SET и COMPONENT с их вложенными компонентами.
2. Покажи таблицу: имя в Figma → предлагаемое имя React, число вариантов, зависимости. Пользователь выбирает (multiSelect) и подтверждает **один пакетный план**. Отдельные вопросы задавай только по неоднозначным местам.
3. Создай сущности в порядке зависимостей (поле parent) и веди их через `craftui next` по одной.
4. **Наборы иконок** (десятки вариантов только из векторов): предложи стратегию — именованный экспорт на иконку (`IconArrowRight`) в `src/components/Icons/` (tree-shaking), visual-тесты на выборке из 5–10 штук. Стратегию подтверждает пользователь.
5. Для кита в chrome-режиме можно сразу выгрузить все переменные файла и заполнить `tokens.css` до компонентов.

## rstest (`craftlog/tests/<Name>.test.tsx`)

Заготовка уже проверяет рендер, `ref`, `className`, проброс атрибутов и каждый `data-*` вариант. Дополни её тестами, которых требует API:
- `disabled` → элемент disabled, `onClick` не вызывается (`userEvent.click`);
- `loading` → `aria-busy="true"`, клик заблокирован;
- слоты и текстовые пропсы рендерятся;
- клавиатура: Enter/Space у интерактивных элементов, видимый фокус (атрибуты, а не стили);
- любая нетривиальная логика (хуки, обработчики).

Тестов немного, но каждый проверяет поведение, а не разметку целиком. Запуск: `npm test -- <Name>`.

## Демо (`<Name>.demo.tsx`)

`defineDemo({ component, figma, targets, defaults, slots })`. У компонента в демо две страницы:
- **Свойства** (`#/components/<Name>`): витрина — блок на каждое свойство, в нём компонент со всеми значениями (enum, boolean, пресеты слотов, псевдосостояния из Figma), по одному значению в строке. Ниже — состояния из Figma, тоже по одному в строке: React и эталон с diff% рядом. Затем таблица API;
- **Песочница** (`#/components/<Name>/playground`): контролы для всех свойств, превью, код JSX с копированием.

Поля demo-файла:
- `targets` — по одному на вариант Figma: `id` совпадает с файлом эталона, `pseudo` задаёт статичные hover/active/focus, `focus` — CSS-селектор элемента внутри target, который получает настоящий фокус (Figma «Focused» у поля ввода: `focus: 'input'`), `frame` — размер обёртки. Состояния, которых нет в Figma, но которые полезно показать, добавляй с id без эталона: скриншот-тест их пропустит;
- `defaults` — базовые пропсы витрины и песочницы (scaffold берёт props target `default`);
- `slots` — варианты содержимого для `ReactNode`-пропсов: `{ contentLeft: { Иконка: <IconPlasma /> }, hint: { Value: 'Value' } }`. Scaffold ставит заглушки `slot('contentLeft', 24, 24)` размера содержимого из макета — замени их содержимым: иконки через `craftui build {"action":"svg",…}` (размер берётся из `targets[].slots`, например `<IconPlasma16 size={12} />` в xxs), тексты из targets. Добавь и текстовый пресет для слотов, куда можно передать текст: так видно, что компонент не ограничивает содержимое.

Контролы строятся из `demo/.generated/props.json` (`npm run gen`): union строк → список, `boolean` → флажок, строки и `children` → поле ввода, `ReactNode` → слот (и `children`, если для него есть `slots.children` — иконка IconButton). В таблицу попадают и нативные атрибуты, которые есть в Figma (например `disabled` у `<button>`).
