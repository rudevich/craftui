# Проверка: `npm run craftui -- verify <Name>`

Одна команда проверяет единицы (только `px` и `%`, см. `code-conventions.md`), затем запускает typecheck, rstest и скриншот-тесты и печатает сводку не длиннее 30 строк. Полные логи пишутся в `craftlog/visual/output/*.log`.

```
typecheck ✓
rstest ✓ 6 passed, 0 failed
visual ✗ 2/3 (порог 1.0%)
  accent-default:
    diff 17.62% (964 px), Figma 53×24, React 57×24
    root: padding-left ожидалось 8px, получено 10px        ← style-check: что именно поправить
    root/label: color ожидалось #ffffff, получено rgb(255, 212, 0)
    размер Figma 53×24, React 57×24
    область x8 y4 40×16: Figma #acccf7, React #acb154 (619 px)
```

## Как работает скриншот-тест

- Для каждого `craftlog/figma/screenshots/<id>.png` тест открывает `/#/components/<Name>?target=<id>&isolated` — один target на прозрачной странице.
- Снимок обёртки `[data-cu-target]` делается с `deviceScaleFactor = scale` из конфига (по умолчанию 2), поэтому пиксели совпадают с экспортом Figma.
- Target из `screenshots/bounds.json` (оверлей, тень за рамкой узла) снимается областью страницы с тем же смещением: компонент должен рисовать оверлей там же, где Figma (`position: absolute` под полем), иначе разойдутся размеры.
- pixelmatch считает долю отличающихся пикселей. Проходит, если доля ≤ `maxDiffRatio` (по умолчанию 1%) и размеры совпадают с точностью до 1 CSS px.
- Результаты лежат в `craftlog/visual/output/`: `<id>.actual.png`, `<id>.diff.png` (красное — отличия) и `<id>.json` с отчётом. Демо показывает эталон рядом с живым рендером и diff%.
- Узлы-содержимое слотов (`slot` в spec) style-check пропускает: их размер задаёт содержимое, а не компонент.
- **Style-check** сравнивает вычисленные стили элементов (по `node-map.json`) со значениями Figma (`expect` в spec): размеры, padding, gap, радиусы, фон, цвет, типографику. Он ничего не блокирует, но называет конкретное свойство, поэтому начинай исправления с него. Читай его и у прошедших targets: короткая подпись, сдвинутая на 8px, даёт меньше 1% отличий и проходит порог, а style-check покажет `padding-left ожидалось 34px, получено 42px`. Сравнение идёт по тому, что нарисовано: прозрачность — произведение `opacity` по пути слоёв в Figma и по предкам элемента в коде (затемнённая обёртка = затемнённые слои внутри), `opacity` текста и альфа его цвета (`color-mix`) взаимозаменяемы, любые полностью прозрачные цвета равны, размеры — с допуском 1.5px (Figma округляет ширину текста). Ожидаемый шум: размеры нарисованного на CSS спиннера и высота строки с курсором-прямоугольником в состояниях Focused. Вертикальный padding из Figma переноси, даже если высота задана явно и содержимое по центру: вид не меняется, а style-check не шумит. Обёртки без своих стилей normalize схлопывает (и с прозрачностью, и с оверлеем-спиннером рядом); если какая-то осталась — поставь ей `null` в node-map.

## Цикл исправлений

1. Начинай с текстового отчёта: строки style-check → «размер» → «контент» (сдвиг) → «области» (где и какие цвета).
2. Если у **всех** targets примерно одинаковый процент, причина общая, и почти всегда это шрифт:
   - шрифт не загрузился — проверь в демо, что `document.fonts` содержит нужное начертание со статусом `loaded`. Шрифты подключаются в `demo/fonts.ts`; фирменные шрифты кита ищи на CDN дизайн-системы (у Salute — `cdn-app.sberdevices.ru/shared-static/0.0.0/styles/SBSansDisplay.0.2.0.css`);
   - текст жирнее, чем в Figma, — нет `-webkit-font-smoothing: antialiased`;
   - остаётся ~1.5–2% — метрики шрифта: базовая линия может отличаться на 1px, а Figma округляет ширину текстового слоя до целого. Это не ошибка вёрстки: опиши пользователю с цифрами и спроси, принять ли порог (например 4%) или компенсировать сдвигом.
3. Остальные типичные причины: забыт `box-sizing: border-box`; line-height; gap или padding; радиус; токен темы не подключён; иконка не того размера; обводка через `border` вместо `inset box-shadow`.
3. Если модель умеет смотреть изображения, а текста мало, — смотри `<id>.diff.png`, затем эталон и `<id>.actual.png`.
4. Правка → `npm run craftui -- verify <Name> --grep <id>` → в конце полный verify.
5. Не больше 5 итераций. Итог каждой записывай: `npm run craftui -- log <Name> "итерация N: …"`.
6. Расхождения после 5 итераций или чисто косметические (сглаживание шрифта, субпиксели, тени) опиши в отчёте с процентами и предложи пользователю: принять (порог), поправить вручную или упростить.

## visual.config.json

`craftlog/visual/visual.config.json`:

```json
{
  "default": { "threshold": 0.1 },
  "targets": {
    "primary-hover": { "maxDiffRatio": 0.03, "reason": "тень в Figma мягче, согласовано 2026-10-25" },
    "with-avatar": { "mask": [{ "x": 8, "y": 8, "w": 24, "h": 24 }], "reason": "фото меняется" },
    "loading": { "skip": true, "reason": "анимация" }
  }
}
```

- `threshold` — чувствительность к цвету одного пикселя (0…1, по умолчанию 0.1).
- `maxDiffRatio` — допустимая доля отличающихся пикселей.
- `mask` — прямоугольники в CSS px, которые не сравниваются.
- `skip` — не сравнивать. `craftui verify` показывает такие targets отдельно («пропущено N» и `reason`) и не считает провалом. Так помечают ошибку макета (заливка не на том слое), пока пользователь не решил, как правильно.

### Маски

- Маска закрывает несравнимое, а не весь оверлей. Если в макете есть часть, которую не делаем (колонка быстрых периодов слева от календаря), закрой содержимое и смещённые края. Поле, отступ до карточки, её совпадающие края и тень оставь в сравнении.
- Координаты маски — в системе скриншота target: при `bounds.json` начало координат сдвинуто на `-bounds.x`, `-bounds.y`. Считай маски скриптом из размеров макета (высота поля, отступ, padding карточки), а не на глаз.
- Подписи и даты, которые в макете условные (месяц, который не совпадает с днями недели), закрывай точечно, по одной области на подпись.

Каждое ослабление проверки — только с `reason` и записью в раздел лога «Отклонения от макета», согласованной с пользователем. Эталон из Figma не перезаписывай никогда.
