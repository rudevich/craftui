# Вид page: адаптивные страницы

Страница — экран из Figma, свёрстанный на нескольких ширинах. Лежит в `src/pages/<Page>/` (папка — `dirs.page` в `craftui.config.json`), устройство как у компонента: `craftlog/`, демо, тесты, README. Конвейер свой: шаги называются так же, но extract, normalize, scaffold и brief у страницы другие.

## Брейкпоинты

Брейкпоинты задаёт пользователь, один раз на проект, в `craftui.config.json` → `pages.breakpoints`. От ширины фреймов они не зависят. Пока они не заданы, `craftui new page` останавливается. Спроси пользователя (AskUserQuestion, по одному вопросу):

1. mobile — до скольки px включительно? (обычно 767)
2. tablet — от mobile+1 до скольки px? Пусто — tablet не нужен.
3. desktop — до скольки px? Пусто — без верхней границы, large desktop не нужен.
4. Если desktop ограничен, large desktop — всё, что шире.

Затем: `npm run craftui -- breakpoints mobile=767 tablet=1279 desktop=`. Без аргументов команда показывает текущие диапазоны. В конфиге они хранятся явно:

```json
"pages": {
  "breakpoints": { "mobile": { "max": 767 }, "tablet": { "min": 768, "max": 1279 }, "desktop": { "min": 1280 }, "largeDesktop": null },
  "scale": 1,
  "maxDiffRatio": 0.02,
  "export": true
}
```

- **Ввод руками:** `min`, равный `max` предыдущего диапазона, значит «больше»: `mobile ≤ 600`, `tablet 600–1024` читается как tablet 601–1024.
- **Фреймы:** фрейм Figma относится к диапазону, куда попадает его ширина. 375 → `mobile`, 1440 → `desktop`, это id targets.
- **Предупреждения normalize:** фрейм вне диапазонов, два фрейма в одном диапазоне, диапазон без фрейма. Последний случай — верстай по соседним брейкпоинтам.
- **Смена брейкпоинтов** готовые страницы не трогает. Новый черновик даёт `craftui scaffold <Page> --force`.

## Импорт по шагам

1. **Разведка.** `npm run craftui -- snippet "<ссылка>" probe` на группе, секции или странице Figma: в `frames` — фреймы с шириной и диапазоном. Ссылка несёт только узел, выделение в Figma в неё не попадает — нужна ссылка на группу экрана или на каждый фрейм.
2. **Создание.** `npm run craftui -- new page <Page> "<ссылка>"`: ссылка на группу или секцию с фреймами экрана — каждый фрейм станет брейкпоинтом. Иначе ссылка на первый фрейм, остальные — `npm run craftui -- source <Page> add "<ссылка>"`. Источник — только chrome (Chrome MCP).
3. **extract.** `snippet <Page> extract`. Сниппет страницы сохраняет все фреймы и собирает слои с картинками. Сериализация слоёв общая с компонентами.
4. **normalize.** targets — брейкпоинты, у каждого `frame.width` = ширина фрейма. Экземпляры компонентов — в `instances`. Предлагаются части — контейнеры верхнего уровня.
   - **Фрейм без auto-layout** (слои по x/y) становится колонкой: порядок по y, промежутки — `margin-top`, выравнивание — `align-self`. На широких брейкпоинтах колонка по центру: `padding: max(<поля mobile>px, calc((100% - <колонка>px) / 2))`. Слой, наехавший на соседа, остаётся `position: absolute`.
   - **Тексты:** `line-height` в процентах пересчитывается в целые px, как рисует Figma (16px × 140% → 22px). Перенос Shift+Enter (U+2028) становится `\n` с `white-space: pre-line`.
   - **Текст в слое экземпляра** (без TEXT-свойства, как «Подтвердить» в кнопке) попадает в текстовый проп компонента.
5. **confirm.** Согласуй брейкпоинты, части и компоненты.
   - **Часть** — `npm run craftui -- part <Page> <слой> <Имя>` (`--remove` убирает). Экземпляр библиотеки (шапка кита) частью верстается из своих слоёв: команда делает его inline и сама запускает normalize.
   - **Общая часть** — `--shared`: шапка, навигация, степпер, которые повторятся на других страницах. Лежит в `src/pages/parts/<Имя>/` с `part.json`. Следующая страница получит её в «общие части, уже сделанные» и возьмёт готовой, не перегенерируя.
   - **Макет устройства** (статус-бар телефона, панель браузера) — `npm run craftui -- skip <Page> <слой>`: слой не верстается. Прижатый к верху фрейма укорачивает страницу, а verify сравнивает эталон ниже него.
   - **Компонент из кита** с другим ключом (кит импортирован из копии файла) — `npm run craftui -- deps <Page> --same "<экземпляр>" <Компонент>`.
6. **screenshots.** `snippet <Page> export`: PNG фреймов в масштабе `pages.scale` (1x) и картинки (PNG 2x, вектор — SVG).
7. **deps.** Компонент из `src/components` берётся как есть. Не импортирован — сначала `new component <Имя> <url> --parent <Page>`, или он встраивается (`deps <Page> --inline "<имя>"`).
8. **tokens** — как у компонента.
9. **scaffold.** Создаёт страницу, части, демо (target на брейкпоинт), тесты и копии картинок в `assets/`.
10. **code**, **tests**, **verify**, **report.** Данные — `craftui brief <Page>`, точечно — `craftui spec <Page> <брейкпоинт> <слой>`.

## Что генерирует scaffold

```
src/pages/<Page>/
  <Page>.tsx, styles.module.css, types.ts, index.ts, <Page>.demo.tsx
  parts/<Page><Part>/   внутренние компоненты страницы: <Page><Part>.tsx, styles.module.css
  assets/               картинки из макета
  craftlog/             как у компонента
```

- **Разметка** — слои всех брейкпоинтов вместе: порядок самого широкого фрейма, слои только узких фреймов встают после своих соседей. Слой, которого нет на брейкпоинте, скрыт в CSS (`display: none`).
- **CSS** — mobile-first. База — самый узкий фрейм. Для каждого следующего — `@container (min-width: <min диапазона>px) { … }` с отличиями. Корень `.root` — контейнер (`container-type: inline-size; width: 100%`), под ним `.frame` — слой фрейма Figma. Контейнер безымянный: CSS Modules делают имя контейнера локальным для файла, и запросы частей его бы не нашли.
- **Широкий слой** фиксированной ширины (от половины фрейма) → `width: 100%; max-width: <ширина>px`.
- **Часть** — свой CSS-модуль. В node-map её классы пишутся как `<Page><Part>/<класс>`, по ним проверка стилей находит элементы. Префикс страницы в имени папки нужен, чтобы классы демо (`[folder]__[local]`) не совпали с компонентами.
- **Общая часть** — `src/pages/parts/<Имя>/`, классы `<Имя>/<класс>`. Имя не должно совпадать с компонентом. Её делает первая страница, другие импортируют `../parts/<Имя>`. Данные, которые меняются от страницы к странице (заголовок, текущий шаг), — пропсы части.

## Компоненты на странице

- Экземпляр импортированного компонента → `<Button className={styles.cta} view="accent">Купить</Button>`. Значения Figma переводятся в пропсы по spec компонента, тексты — в его текстовые пропсы.
- **API и стили компонента не меняются.** Страница задаёт только его место и размер: `align-self`, `flex`, `width`, `height`, `margin-*`, позицию. Остальные свойства из Figma черновик отбрасывает. Отступы экземпляра, переопределённые в макете, style-check покажет замечанием — высоту держит `height` страницы.
- **Проп зависит от ширины** (size m на mobile, l на desktop): в разметке пропсы самого узкого брейкпоинта, над элементом комментарий, в brief предупреждение. Реши: один проп для всех ширин или переключение по ширине контейнера.

## Правила кода страницы

- **Ширина:** у страницы нет фиксированной ширины, она заполняет родителя. Размеры только `px` и `%`, в том числе в условиях `@container`.
- **Брейкпоинты** — только из конфига. Не придумывай свои и не ставь медиазапросы по окну (`@media`).
- **Семантика:** `header`, `main`, `section`, `footer`, `nav`, заголовки `h1`–`h3` по смыслу. Черновик пишет `div` и `span`, их заменяют на шаге code. У `h1`–`h3` и `p` обнули `margin` браузера, отступы — из черновика. Текст из нескольких абзацев — `<p>` на абзац, пустая строка между ними — `margin-top` в одну высоту строки.
- **Картинки:** `<img>` с `alt` по смыслу, декоративные — `alt=""`. `object-fit: cover` из черновика оставь.
- **Тексты:** из макета, как есть. Данные и ссылки страница не выдумывает. Нужны пропсы — согласуй с пользователем.

## rstest

Заготовка проверяет рендер, `ref` и `className` корня, `alt` у всех картинок. Допиши:
- тексты и ссылки на месте;
- части отрисованы;
- компоненты получили пропсы из макета (роль и имя, `toHaveAttribute`).

## Проверка

`npm run craftui -- verify <Page>`:
- каждый брейкпоинт снимается в рамке ширины своего фрейма и сравнивается с PNG фрейма;
- порог и масштаб берутся из `pages.maxDiffRatio` и `pages.scale`, браузер снимает в том же масштабе;
- **плотный текст** (оферта, декларация) в 1x даёт 5–10% шума растеризации даже при совпадающих строках. Поставь `pages.scale: 2`, затем переэкспортируй эталоны (`snippet <Page> export`). Остаток (Chromium рисует жирные шрифты плотнее Figma) — порог target в `visual.config.json` с `reason` и записью в лог;
- style-check находит элементы частей по классам `<Page><Part>__<класс>`.

## Ограничения

- Только источник chrome (Chrome MCP). Figma MCP для страниц пока не поддержан.
- `brief` сокращает длинные тексты до начала: полный текст — в черновике разметки.
- Части не вкладываются друг в друга: слой внутри части — её разметка.
- Пропсы компонентов, зависящие от ширины, решаются на шаге code.
- Режимы переменных на слоях (тёмная тема на градиенте, типографика ExtraSmallScreens у заголовка) черновик пока не переносит: тёмную тему дай атрибутом `data-theme="dark"` на блоке, размеры типографики другого режима — значениями в правиле нужного брейкпоинта.
