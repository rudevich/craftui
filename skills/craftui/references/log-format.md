# Лог, состояние, итоговый отчёт

## `craftlog/craftui.log.md` — для человека

Создаётся командой `craftui new`. Разделы между маркерами `<!-- craftui:… -->` перезаписывают команды. Остальное заполняет агент.

| Раздел | Кто пишет |
|---|---|
| Шапка: вид, ссылка, fileKey/nodeId, источник, дата | `craftui new` |
| Шаги (статусы, попытки, ошибки) | `craftui begin/done/fail/wait` |
| Свойства (Figma → React) | агент на шаге confirm: таблица из `normalize --summary` после согласования |
| Targets (id, вариант, node, статус, diff) | `craftui verify` |
| Зависимости: использует / используется в | агент на шаге deps (`craftui new … --parent` пишет историю автоматически) |
| Токены и ассеты | агент (по выводу `craftui tokens`), шрифты |
| Отклонения от макета | агент: что, почему, кто согласовал, где ослаблена проверка |
| Компромиссы | `craftui shortcuts` (комментарии `shortcut:`) |
| История | append-only: `craftui log`, все команды craftui, принятые планы, задачи пользователя |

Пиши коротко и фактами: «итерация 2: radius 8→6, line-height 20px; diff 4.1% → 0.6%».

## Версии импорта и README.md

- **Версия импорта** — номер завершённого цикла: первый `craftui done <Name> report` даёт версию 1, каждый следующий после `craftui reopen <Name> <step> "<причина>"` — +1. Версии с датой и причиной хранятся в `state.json` → `imports`. Причину передавай в `reopen` всегда: она попадёт в историю версий.
- **`<папка сущности>/README.md`** — для людей: таблица свойств из типов компонента, версия и дата импорта, первый импорт, ссылки на наборы Figma, итог последней проверки, пример использования, вложенные части, отклонения и компромиссы из лога, история версий. Генерируется при завершении шага report, при `npm run gen` (то есть при `dev` и `build`) и командой `npm run craftui -- readme [Name]`. Вручную не редактируется: текст для людей пиши в лог (разделы «Отклонения от макета», «Компромиссы») или в описание компонента в Figma.

## Итоговый отчёт пользователю (шаг report)

Коротко, по пунктам:
1. Где лежит компонент и как его посмотреть: `npm run dev` → `http://localhost:4600/#/components/<Name>`.
2. API: пропсы и их значения (таблица из лога); что из макета сознательно не стало пропсом.
3. Проверка: rstest N/N; targets X/Y с diff% (худшие три с причинами).
4. Токены: добавлено N, конфликты (если есть).
5. Вложенные компоненты: импортированы, inline.
6. Компромиссы и отклонения.
7. Как дать правки: «поправь <Name>: …».
8. Последние 1–2 строки: что не проверено и какие риски.

Затем `npm run craftui -- done <Name> report` — это закрывает версию импорта и обновляет README.md; номер версии назови пользователю в отчёте.
